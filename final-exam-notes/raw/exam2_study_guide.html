CPSC 375 · Exam 2 · Lectures 15–31

Lec 15
Parallel Algorithm Design

Task/data decomposition strategies. Dependency analysis. Foster's methodology: partition → communicate → agglomerate → map (PCAM).

Lec 16–17
Shared-Memory Programming with OpenMP

Compiler directives (#pragma omp parallel, parallel for). Private vs. shared variables. Race conditions and the reduction clause. Scheduling: static, dynamic, guided. Barriers, atomic, critical, nowait. Sections and task parallelism. Timing with omp_get_wtime().

Lec 18–22
Threads, Sockets, and Concurrency Primitives

POSIX threads (pthreads). Mutexes and condition variables. Producer/Consumer pattern. Thread pools. Critical sections, signals, sockets. Deadlock and lock ordering.

Lec 20–22
Distributed-Memory Programming with MPI

Point-to-point: MPI_Send / MPI_Recv. Collective: MPI_Bcast, MPI_Reduce, MPI_Scatter, MPI_Gather, MPI_Allgather. Communicators, rank, size. Trapezoidal rule example. Running with Slurm.

Lec 23–24
Sieve of Eratosthenes

Sequential algorithm and complexity O(n ln ln n). Domain decomposition with MPI. Optimizations: eliminate even integers, eliminate broadcast via local sequential sieve, reorganize loops for cache efficiency (blocking/tiling).

Lec 25, 28–29
Parallel Sorting Algorithms

Odd-even (transposition) sort: n phases of compare-and-swap. Shearsort: alternating row/column sorts on a 2D mesh, snake-order for rows. Parallel merge sort. Analysis of communication steps vs. sequential comparison.

Lec 27–28
Performance Analysis

Speedup S = Ts/Tp. Efficiency E = S/p. Amdahl's Law (strong scaling, fixed problem). Gustafson's Law (weak scaling, scaled problem). Karp–Flatt metric (empirical serial fraction, diagnoses overhead). Strong vs. weak scaling.

Lec 30–31
Parallel Matrix Multiplication

Sequential O(n³) baseline. Block-striped decomposition. Tiling for cache efficiency. Cannon's algorithm: checkerboard decomposition, initial skewing, shift-multiply phases. Fox's algorithm: broadcast-and-shift, outer-product formulation. SUMMA algorithm.

OpenMP
race condition
Multiple threads read/write shared data with no synchronization, producing unpredictable results
reduction clause
Safely combines per-thread partial results into a single value (e.g., sum, max)
critical section
Code block that only one thread executes at a time
atomic
Hardware-level single-operation mutual exclusion; faster than critical for simple updates
barrier
Synchronization point where all threads must arrive before any proceeds
nowait
Removes the implicit barrier at end of a for/sections construct
dynamic scheduling
Threads receive iterations on demand; better for uneven workloads
static scheduling
Iterations divided evenly and assigned at compile time; low overhead
guided scheduling
Large chunks assigned first, chunks shrink over time; balances load
MPI
communicator
Group of processes that can communicate (default: MPI_COMM_WORLD)
rank
Unique integer ID of a process within a communicator
MPI_Bcast
One process sends the same data to all others in the communicator
MPI_Reduce
Combines values from all processes into a single result on one process
MPI_Scatter
Distributes distinct chunks of an array from root to all processes
MPI_Gather
Collects chunks from all processes into a single array on root
MPI_Allgather
Every process receives the concatenated send buffers of all processes
blocking send/recv
Process waits until the operation completes before continuing
Performance
speedup (S)
S = Ts / Tp — ratio of serial time to parallel time on p processors
efficiency (E)
E = S / p — fraction of time each processor does useful work
Amdahl's Law
S = 1/(f + (1−f)/p); speedup limited by serial fraction f; strong scaling
Gustafson's Law
S = p − f(p−1); problem size scales with p; weak scaling, optimistic
Karp–Flatt metric
e = (1/S − 1/p)/(1 − 1/p); empirical serial fraction; rising e means overhead
strong scaling
Fixed problem size, increase p — measures parallel efficiency ceiling
weak scaling
Problem size grows with p — measures if you can solve bigger problems faster
Algorithms
domain decomposition
Partition data across processes; each handles its own subarray
functional decomposition
Partition tasks/stages across processes; each does a different kind of work
odd-even sort
n phases; odd phases compare odd-even pairs, even phases compare even-odd pairs
shearsort
Alternating row/column sorts on a √p×√p mesh; rows sort in snake order
Cannon's algorithm
Checkerboard matrix multiply; skew A and B, then shift-multiply √p times
Fox's algorithm
Checkerboard matrix multiply; broadcast A block along rows, shift B along columns
tiling / blocking
Reorganize loops so data fits in cache; improves cache hit rate
Speedup & Efficiency
S_p = T_s / T_p
E = S_p / p = T_s / (p · T_p)
Amdahl's Law (strong scaling)
S_p = 1 / (f + (1 − f)/p)

As p → ∞, S_p → 1/f
f = serial fraction of the program

Assumes fixed problem size. Pessimistic upper bound on speedup.

Gustafson's Law (weak scaling)
S_p = p − f(p − 1) = f + p(1 − f)

Assumes T_p = 1, split into serial f and parallel (1 − f)

Problem grows with p. Speedup grows without bound as f → 0.

Karp–Flatt Metric
e = (1/S_p − 1/p) / (1 − 1/p)

e = experimentally determined serial fraction

If e increases as p grows, overhead (communication, sync) is the bottleneck — not the serial fraction alone.

Sieve of Eratosthenes complexity
Sequential: O(n ln ln n)
Parallel (domain decomp): O(n ln ln n / p + √n ln ln √n)
Odd-Even Sort
n phases total (n = number of elements / processes)
Each phase: compare-and-swap with neighbor
Parallel time: O(n) phases
Shearsort
Grid: √p × √p processes
Phases: ⌈log₂ p⌉ + 1 row/column sort pairs
Each sort: O(√p log √p)
Matrix Multiplication (sequential)
C[i][j] = Σ A[i][k] · B[k][j], k=1..n
Sequential complexity: O(n³)
Cannon's Algorithm
p processes on √p × √p grid
Each process: (n/√p) × (n/√p) block
Communication-to-computation ratio: n/√p
Steps: skew once, then √p shift-multiply phases
